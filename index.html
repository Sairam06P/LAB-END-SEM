Experiment overview

Aim

To demonstrate Git version control by creating branches, committing changes and merging a feature branch into the main branch.

Tools required

Git, Visual Studio Code, a web browser and GitHub for remote repository hosting.

Learning objectives

Understand independent development, track changes, combine work and verify repository history.

Understanding Git

Repository

A project and its tracked version history.

Branch

An independent line of development that allows changes without disturbing the main branch.

Commit

A recorded snapshot of staged changes with a descriptive message.

Merge

Combines changes from different branches into the current branch.

Step-by-step procedure

For a fresh practice repository, follow these steps. This supplied project already contains a completed merge.

  1. Create a project folder and initialize Git.git init -b main
  2. Create index.html, stage it and commit the initial website.git add .
    git commit -m "Create website"
  3. Create and switch to a feature branch.git switch -c feature-about
  4. Add an About section to the HTML file and commit the changes.git add index.html
    git commit -m "Add about section"
  5. Return to main and merge the feature branch.git switch main
    git merge --no-ff feature-about
  6. Verify the branches, history and working tree.git branch
    git log --oneline --graph --all
    git status

Types of merging

Fast-forward merge

Moves the current branch pointer forward when there are no divergent commits.

Three-way merge

Combines divergent changes using a common ancestor and normally creates a merge commit.

Merge conflict

Occurs when Git cannot automatically combine competing changes. Edit the conflicting file, stage it and commit the resolution.

Important Git commands

Command Purpose
git status Check working tree and staging area
git branch List local branches
git add . Stage changes
git commit -m "message" Record staged changes
git merge feature-about Merge feature changes into current branch
git push Upload commits to a remote repository

Inference and result

Inference

Git branches allow developers to work independently while maintaining a stable main branch. Commits provide a traceable history, and merging integrates completed changes.

Result

The feature-about branch was successfully merged into main. The website contains both the original workflow and the branch demonstration, and the merge commit is preserved in the repository history.
